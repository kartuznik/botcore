# botcore

[![CI](https://github.com/kartuznik/botcore/actions/workflows/ci.yml/badge.svg)](https://github.com/kartuznik/botcore/actions/workflows/ci.yml)

Каркас Telegram-бота на aiogram 3 с модульной архитектурой: ядро отвечает за проводку, функции живут в отдельных модулях.

## Что это

`botcore` — это композиционный корень и набор швов, а не готовый продукт. Ядро (`core/`) читает конфигурацию, настраивает логирование, подключает middleware, поднимает хранилище и запускает поллинг с корректным завершением. Функциональность добавляется модулями (`modules/`): каждый модуль отдаёт `Router`, регистрируется в реестре по имени и включается переменной окружения — ядро при этом не меняется.

Сейчас в комплекте два модуля: `health` для проверки живости и `raffle` для розыгрышей.

## Быстрый старт

```bash
git clone https://github.com/kartuznik/botcore.git
cd botcore
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env
```

Откройте `.env` и впишите `BOT_TOKEN` — токен выдаёт [@BotFather](https://t.me/BotFather). Затем запустите:

```bash
python -m core
```

Без токена бот не стартует: печатает подсказку и завершается с кодом `1`, без трейса.

## Конфигурация

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BOT_TOKEN` | — | Токен бота. Обязательна: без неё процесс завершается с кодом `1`. |
| `MODULES` | `health` | Включённые модули через запятую. Порядок значим, `health` держите последним. |
| `LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR` или `CRITICAL`. Неизвестное значение — откат к `INFO`. |
| `STORAGE_PATH` | `data/botcore.db` | Файл SQLite: хранилище ядра и таблицы модуля `raffle`. |
| `RAFFLE_ADMIN_ID` | — | Telegram id администратора розыгрышей, можно несколько через запятую. Пусто — модуль `raffle` не поднимается. |

Значения берутся из окружения процесса, а недостающие догружаются из файла `.env` в рабочей директории с `override=False` — то есть реальное окружение всегда побеждает файл. Сам `.env` в git не попадает, и его содержимое не пишется в логи: при старте логируется только путь к файлу.

## Модули

### health

Проверка живости и точка входа для пользователя.

| Команда | Кто может | Что делает |
|---|---|---|
| `/start` | все | Приветствие и список включённых модулей. |
| `/help` | все | Список команд. |

Модуль также отвечает на любое необработанное сообщение, поэтому в `MODULES` он должен идти последним — иначе перехватит команды модулей, перечисленных после него. Если порядок нарушен, модуль пишет об этом warning в лог.

### raffle

Розыгрыши с условием подписки, тиражом и демо-режимом. Включается как `MODULES=raffle,health` и требует `RAFFLE_ADMIN_ID`; без этой переменной модуль не поднимается, бот стартует и работает остальными модулями.

Администратор — это владелец id из `RAFFLE_ADMIN_ID`. Остальные пользователи получают на админские команды вежливый отказ.

| Команда | Кто может | Что делает |
|---|---|---|
| `/newraffle` | админ | Форма из четырёх шагов: название, число победителей, дедлайн, каналы. Подтверждение и отмена — inline-кнопками. |
| `/raffles` | все | Список розыгрышей: статус, дедлайн, условие подписки, число участников. |
| `/join <id>` | все | Вступление. Один вход на пользователя, только пока розыгрыш открыт и дедлайн не прошёл. |
| `/draw <id>` | админ | Тираж: перепроверка подписки, выбор победителей, запись протокола. |
| `/demodraw [участники] [победители]` | админ | Тот же механизм на демо-таблицах. Вместо числа участников можно передать список id: `/demodraw 11,22,33 2`. |
| `/cancel` | все | Прерывает незавершённую форму. |

Дедлайн принимается относительным (`30m`, `2h`, `3d`), голым числом (`2` — это два часа) или точным (`2026-09-20 18:00`, `20.09.2026`); время в UTC. Каналы задаются как `@name`, `t.me/name` или числовой `-100…`.

Победители выбираются только среди тех, кто вступил в открытом окне и на момент тиража всё ещё подписан на все указанные каналы: подписка перепроверяется через `get_chat_member`, отписавшиеся исключаются с указанием причины. Выборка делается `secrets.SystemRandom().sample`, победители уникальны. Seed не сохраняется и воспроизводимость тиража не обещается — вместо этого в таблицу `draws` пишется протокол: снимок всех участников, список допущенных, список исключённых с причинами и итоговые победители.

Если бот не администратор канала, тираж не начинается: админ получает понятное сообщение, розыгрыш остаётся открытым, ничего не записывается. Данные лежат в шести таблицах: `raffles`, `participants`, `draws` и зеркальные `demo_raffles`, `demo_participants`, `demo_draws` — демо-режим отделён таблицами, а не колонкой-флагом, поэтому демонстрация не может задеть боевые данные.

## Тесты и качество

```bash
ruff check .
ruff format --check .
mypy core modules
pytest -q
```

`mypy` работает в режиме `strict` и покрывает и `core/`, и `modules/`. Те же четыре команды выполняет GitHub Actions на каждый push и pull request, на матрице Python 3.11 и 3.14.

## Деплой

Юнит systemd лежит в репозитории: `deploy/botcore.service`. Он запускает `python -m core` из каталога проекта, поэтому `.env` подхватывается оттуда же.

```bash
install -m 644 deploy/botcore.service /etc/systemd/system/botcore.service
systemctl daemon-reload
systemctl enable --now botcore
```

Рабочие команды:

```bash
systemctl status botcore
systemctl restart botcore
journalctl -u botcore -f
```

## Эксплуатационные правила

**Ровно один экземпляр на токен.** Telegram отдаёт апдейты одному потребителю `getUpdates`, поэтому второй процесс с тем же токеном получит `TelegramConflictError` и будет бесконечно переподключаться. Симптом — «бот не отвечает» при живом и активном сервисе. Перед запуском убедитесь, что нет забытых ручных запусков.

**Остановка — это graceful shutdown.** По `SIGTERM` бот перестаёт забирать новые апдейты, дожидается тех, что уже в работе, закрывает хранилище и сессию Telegram. В логе это видно как `stop requested` → `Polling stopped` → `shutdown complete`.

**`TimeoutStopSec=30`.** Столько systemd даёт боту на дренаж перед `SIGKILL`. Значение задано в юните; если хендлеры станут длиннее, увеличивайте его вместе с ними.

## Структура проекта

```
core/                 ядро, менять при добавлении модулей не нужно
  __main__.py         точка входа: python -m core
  app.py              BotApp: middleware, модули, polling, shutdown
  config.py           чтение окружения и .env, fail-fast без трейса
  logging_setup.py    единый формат логов с именем модуля
  middleware.py       логирование апдейтов и глобальный перехват исключений
  registry.py         реестр: имя модуля -> фабрика Router
  storage.py          StorageInterface (Protocol) и SqliteStorage
modules/
  health.py           /start, /help, ответ на неизвестную команду
  raffle/             розыгрыши: форма, вступление, тираж, демо-режим
deploy/
  botcore.service     юнит systemd
tests/                pytest и pytest-asyncio
.github/workflows/
  ci.yml              ruff, mypy, pytest на 3.11 и 3.14
```

## Как добавить модуль

1. Создайте файл модуля: `modules/<name>.py` или пакет `modules/<name>/` с константой `MODULE_NAME`.
2. Опишите фабрику `create_router(context: ModuleContext) -> Router` — она возвращает `Router` со всеми хендлерами. Общие зависимости берите из DI aiogram: `BotApp` кладёт хранилище в `dispatcher["storage"]`, так что хендлер может объявить параметр `storage: StorageInterface`.
3. Зарегистрируйте фабрику в `modules/__init__.py` внутри `build_default_registry()`.
4. Включите модуль через `MODULES=<name>,health` — ваш модуль перед `health`, иначе его команды перехватит обработчик неизвестных сообщений.
5. Добавьте тесты в `tests/` и убедитесь, что `ruff`, `mypy core modules` и `pytest` проходят локально.
