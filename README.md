# botcore

Каркас Telegram-бота на **aiogram 3** и **Python 3.11+**. Здесь только швы: конфиг, логирование,
реестр модулей, хранилище, middleware и composition root. Бизнес-логики нет — кроме модуля
`health`, который доказывает, что проводка работает.

## Структура

```
core/
  __main__.py       # точка входа: python -m core
  app.py            # BotApp — composition root (middleware, модули, polling, shutdown)
  config.py         # чтение env, fail-fast без трейса
  logging_setup.py  # единый формат логов с именем модуля
  middleware.py     # логирование апдейтов + глобальный перехват исключений
  registry.py       # реестр: имя модуля -> фабрика Router
  storage.py        # StorageInterface (Protocol) + SqliteStorage
modules/
  health.py         # /start, /help, вежливый ответ на неизвестное
  raffle/           # розыгрыши: форма создания, вступление, тираж, демо-режим
tests/              # pytest + pytest-asyncio
```

## Переменные окружения

| Переменная | Обязательно | По умолчанию | Описание |
|---|---|---|---|
| `BOT_TOKEN` | **да** | — | Токен от [@BotFather](https://t.me/BotFather). Без него бот печатает подсказку и выходит с кодом `1`. |
| `MODULES` | нет | `health` | Список включённых модулей через запятую. Неизвестное имя — понятная ошибка и выход `1`. |
| `LOG_LEVEL` | нет | `INFO` | `DEBUG` / `INFO` / `WARNING` / `ERROR` / `CRITICAL`. Неизвестное значение — откат к `INFO`. |
| `STORAGE_PATH` | нет | `data/botcore.db` | Файл SQLite: хранилище ядра и таблицы модуля `raffle`. |
| `RAFFLE_ADMIN_ID` | для `raffle` | — | Telegram id администратора розыгрышей, можно несколько через запятую. Пусто — модуль не поднимается. |

Значения читаются из окружения, а недостающие — из файла `.env` в рабочей директории
(шаблон: `.env.example`). Переменные окружения имеют приоритет над файлом, сам `.env`
в git не попадает, и его содержимое никогда не пишется в логи.

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e ".[dev]"

cp .env.example .env          # и вписать BOT_TOKEN
python -m core
```

Остановка — `Ctrl+C` или `SIGTERM`: бот перестаёт забирать новые апдейты и дожидается тех,
что уже в работе, затем закрывает хранилище и сессию Telegram.

Без токена:

```console
$ python -m core
BOT_TOKEN is not set, so the bot cannot start.
...
$ echo $?
1
```

## Проверки

```bash
ruff check .
ruff format --check .
mypy core modules   # strict
pytest -q
```

Те же три шага выполняет GitHub Actions (`.github/workflows/ci.yml`) на каждый push и pull request,
на Python 3.11 и 3.14.

## Деплой на сервер (systemd)

```bash
install -m 644 deploy/botcore.service /etc/systemd/system/botcore.service
systemctl daemon-reload
systemctl enable --now botcore
journalctl -u botcore -f
```

Юнит запускает `python -m core` из рабочей директории проекта, поэтому `.env` подхватывается
оттуда же. `Restart=always` поднимает бота после падения, а `TimeoutStopSec=30` даёт ему дожать
текущие апдейты при остановке — `systemctl stop` и `restart` проходят через штатный graceful
shutdown.

Одновременно должен работать **ровно один** экземпляр бота: Telegram отдаёт апдейты одному
потребителю `getUpdates`, и второй процесс с тем же токеном получит `TelegramConflictError`.
Перед запуском сервиса убедитесь, что нет забытых ручных запусков.

## Как добавить модуль

1. Создайте `modules/<name>.py` с `MODULE_NAME` и фабрикой `create_router(context: ModuleContext) -> Router`.
2. Зарегистрируйте её в `modules/__init__.py` внутри `build_default_registry()`.
3. Включите модуль через `MODULES=<name>,health`.

Общие зависимости приходят в хендлеры через DI aiogram: `BotApp` кладёт хранилище в
`dispatcher["storage"]`, поэтому хендлер может объявить параметр `storage: StorageInterface`.

**Порядок в `MODULES` значим.** Роутеры подключаются в том порядке, в каком перечислены,
а `health` ловит любое необработанное сообщение — держите его последним, иначе он перехватит
команды модулей, стоящих после него. Если это нарушено, `health` пишет об этом warning в лог.

## Модуль `raffle` — розыгрыши

Включается через `MODULES=raffle,health` и требует `RAFFLE_ADMIN_ID`. Без этой переменной
модуль не поднимается: бот стартует, пишет warning в лог и работает остальными модулями.

### Команды

| Команда | Кто может | Что делает |
|---|---|---|
| `/newraffle` | админ | Форма из четырёх шагов: название, число победителей, дедлайн, каналы. Подтверждение и отмена — inline-кнопками. |
| `/raffles` | все | Список розыгрышей: статус, дедлайн, условие подписки, число участников. |
| `/join <id>` | все | Вступление. Один вход на пользователя, только пока розыгрыш открыт и дедлайн не прошёл. |
| `/draw <id>` | админ | Тираж: проверка допуска, выбор победителей, запись протокола. |
| `/demodraw [участники] [победители]` | админ | Тот же механизм на демо-таблицах. Вместо числа участников можно передать список id: `/demodraw 11,22,33 2`. |

Дедлайн принимается относительным (`30m`, `2h`, `3d`) или точным (`2026-09-20 18:00`,
`20.09.2026`), время — UTC. Каналы: `@name`, `t.me/name` или числовой `-100…`.

### Правила тиража

Победители выбираются только среди тех, кто вступил в открытом окне (один вход на пользователя)
и **на момент тиража** всё ещё подписан на все указанные каналы — подписка перепроверяется через
`get_chat_member`, отписавшиеся исключаются с указанием причины. Выборка делается
`secrets.SystemRandom().sample`, победители уникальны. Seed не сохраняется, и воспроизводимость
тиража не обещается — вместо этого в таблицу `draws` пишется протокол: снимок всех участников,
список допущенных, список исключённых с причинами и итоговые победители. Этого достаточно, чтобы
разобрать спорную ситуацию постфактум.

Если бот не администратор канала (или удалён из него), тираж не начинается: админ получает
понятное сообщение, розыгрыш остаётся открытым, ничего не записывается — можно выдать боту права
и повторить `/draw`.

### Данные

Шесть таблиц в том же файле SQLite, что и хранилище ядра: `raffles`, `participants`, `draws` и
зеркальные `demo_raffles`, `demo_participants`, `demo_draws`. Демо-режим отделён именно таблицами,
а не колонкой-флагом, поэтому демонстрация клиенту физически не может задеть боевые данные.
Таблицы создаются при старте модуля. Повторное вступление отсекается ограничением
`UNIQUE (raffle_id, user_id)` на уровне БД, а не только проверкой в коде.

## Границы

- `StorageInterface` — это только `get` / `set` / `delete` / `close` по строковому ключу.
  Схем бизнес-сущностей в ядре нет намеренно: свои таблицы модуль заводит сам.
- `mypy --strict` проходит по `core/` и `modules/`; `tests/` типизированы, но не под strict.
- Бот только уведомляет о результате тиража в чате, где выполнена команда: рассылок победителям
  и постов в канал модуль не делает.
